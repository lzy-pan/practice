# 文档 OCR 工具

把**图片**和**扫描版 PDF** 批量转成可编辑、可搜索的文档。纯本地运行，文件不上传。

支持输出 TXT / Markdown / Word / 可搜索 PDF，另外带一个**实时摄像头识别**窗口，对着纸张就能取字。

![主界面](docs/screenshot.png)

## 为什么用它

- **离线**：RapidOCR 的 ONNX 模型在本机 CPU 推理，不出网、不传云，敏感票据也能处理
- **真·可搜索 PDF**：不是把文字另存一份，而是把不可见文字层按坐标叠回原页，原件外观不变、Ctrl+F 能搜、能选中复制
- **表格不串行**：检测器会把一行切成多个框，程序按垂直中心聚类成行、行内按横坐标拼接并补空格，读出来是 `1　　数控加工中心　　CNC-850　　2　　428,000.00` 而不是一堆乱序碎片
- **不重复劳动**：PDF 某页本来就有文字层（电子版），直接提取，不浪费算力重识别
- **摄像头也能用**：框选一块区域只识别框内文字，等于给摄像头加了个变焦

## 功能一览

| 分类 | 能力 |
|---|---|
| 输入 | `png` `jpg` `jpeg` `bmp` `webp` `tif` `tiff` `pdf` |
| 输出 | `txt` `md` `docx` `pdf`（可搜索） |
| 批量 | 整目录递归导入、拖拽入窗、中途停止、单文件失败不影响其他文件 |
| 报告 | 自动生成 `识别汇总.csv`（页数 / 行数 / 字符数 / 耗时 / 状态 / 产物） |
| 摄像头 | 实时预览 + 实时识别、拖拽框选、绿框叠加、复制文字、拍照回填主列表 |
| 环境 | Windows 优先（带 `.bat` 启动与打包脚本），`core.py`/`cli.py` 跨平台可用 |

## 快速开始

### 环境要求

- Python **3.10**（RapidOCR 目前不支持 3.13，用 3.10 最稳）
- Windows 10/11（界面用 tkinter，系统自带）

### 安装

```bash
conda create -n py310 python=3.10 -y
conda activate py310
pip install rapidocr onnxruntime pymupdf python-docx pillow tkinterdnd2 opencv-python
```

`tkinterdnd2` 只用于拖拽，缺失也能启动（自动降级为按钮导入）；`opencv-python` 只在摄像头功能里需要。

### 启动

```bash
# 方式一：双击（Windows）
run.bat

# 方式二：直接跑
python app.py
```

> `run.bat` 里写死了一个 py310 环境路径，换机器请改成自己的，或直接用 `python app.py`。
> 自检可以执行 `run.bat --check`，它会打印找到了哪个解释器。

## 图形界面用法

1. **加文件**：点「添加文件 / 添加文件夹」，或直接把文件、文件夹拖进窗口
2. **选格式**：右侧默认勾选 TXT + Word + 可搜索 PDF，需要喂给 AI 或做知识库就再勾 Markdown
3. **选输出位置**：默认是当前目录下的 `ocr_output`
4. **点「开始识别」**：进度按**页**递增，日志区实时打印每页用的是原生文字层还是 OCR
5. 完成后弹窗询问是否打开输出目录

左侧列表显示类型、页数、大小；选中按 `Delete` 或双击可移除，支持多选。

| 选项 | 默认 | 说明 |
|---|---|---|
| 输出格式 | TXT + DOCX + PDF | 至少选一个，全不选会退化成 TXT |
| 置信度阈值 | 0.5 | 0.3 多留结果（乱码也多）、0.7 更严格 |
| PDF 已有文字层直接提取 | 开 | 某页原生文字 ≥ 20 字符就跳过 OCR |

## 实时摄像头识别

主界面文件列表下方点「摄像头识别」：

![摄像头识别](docs/camera.png)

1. 选摄像头序号 → 点「打开摄像头」
2. 勾上「实时识别」，画面里文字被持续识别，绿色框标出位置
3. **在画面上按住左键拖一个框**，只识别框内文字 —— 这是提升准确率最有效的手段
4. 右侧显示结果，点「复制文字」进剪贴板
5. 想归档就点「拍照并加入待处理」，截图回到主界面列表，和批量文件一起导出

| 选项 | 说明 |
|---|---|
| 实时识别 | 关掉后只在点「识别当前画面」时识别一次，省 CPU |
| 间隔 | 两次识别的最小间隔（0.3 / 0.5 / 1 / 2 秒），识别慢时会自动拉长 |
| 只识别中央区域 | 只处理画面中间 82%，行数少、更快 |
| 档位 | 「速度优先」适合实时看；「精度优先」更准，慢一倍左右 |
| 拖拽框选 | 只识别框内区域，右键或「清除框选区域」取消 |

**低分辨率摄像头会自动增强**：画面短边不足 720px 时先双三次插值放大（最多 2 倍）再识别，640×480 的老摄像头也能读清小字。

## 命令行用法

```bash
python cli.py 扫描件目录 -o 结果 -f txt,md,docx,pdf
python cli.py a.pdf b.png -o 结果 --min-score 0.6
python cli.py 扫描件 -o 结果 --no-smart        # 已有文字层也强制重新识别
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `inputs` | 必填 | 图片、PDF 或包含它们的文件夹，可多个 |
| `-o, --out` | `ocr_output` | 输出目录 |
| `-f, --formats` | `txt,md,docx` | 逗号分隔：`txt,md,docx,pdf` |
| `--min-score` | `0.5` | 置信度阈值 |
| `--no-smart` | 关 | 关闭「已有文字层直接提取」 |

## 输出说明

每个输入文件生成同名产物，重名会自动加序号 `(1)`，不会覆盖：

```
结果/
├── 采购合同_扫描件.txt                 纯文本（多页带「===== 第 N 页 =====」分隔）
├── 采购合同_扫描件.md                  Markdown（# 标题 + ## 第 N 页）
├── 采购合同_扫描件.docx                Word，正文微软雅黑 10.5pt，多页加二级标题
├── 采购合同_扫描件_可搜索.pdf          保留原件外观 + 不可见文字层
└── 识别汇总.csv                        每个文件的页数/行数/字数/耗时/状态
```

## 性能参考（CPU，无独显）

| 场景 | 耗时 |
|---|---|
| 单张 A4 扫描页（200 dpi 渲染） | 约 3 秒 |
| 小图 520×340（自动放大后识别） | 约 3 秒 |
| 摄像头空画面 | 0.28 秒 |
| 摄像头 5 行票据 | 0.64 秒 |
| 摄像头整帧密排文档 | 1.3~2 秒 |

模型首次加载约 2 秒，批量处理全程只加载一次。行数是主要成本——这也是摄像头框选的原理：少识别几行就快。

## 工作原理

**扫描版 PDF 怎么变成可搜索的**

1. PyMuPDF 以 200 dpi 把每页渲染成位图
2. RapidOCR 检测 + 识别，拿到每行的文本、四点多边形坐标、置信度
3. 把识别结果按 `x * 72/200` 折算回 PDF 点坐标，用 `insert_text(..., render_mode=3)` 写入**不可见**文字层（`render_mode=3` 表示只参与文本提取、不绘制），字体用 PyMuPDF 内置的 `china-s` 保证中文可被提取
4. 原页图片原样保留，所以外观不变、文字可搜

**阅读顺序怎么还原**

检测框先按垂直中心排序聚成行：新框的中心落在当前行高度 55% 范围内即视为同一行；行内按左边界排序拼接，列间距超过行高的 0.8 倍补 4 个空格、超过 0.12 倍补 1 个空格。这是表格能读对的关键。

**小图为什么能提升**

最短边不足 960px 时按 LANCZOS 放大后再识别；坐标会按放大系数折回原图，所以可搜索 PDF 里文字位置仍准确。

**两套识别参数**

| 场景 | 检测输入 | 理由 |
|---|---|---|
| 批量文档 | 默认（短边 736） | 保住小字召回，精度优先 |
| 摄像头 | 最长边 960 | 速度约提升 2 倍，实时预览才跟得上 |

## 项目结构

```
doc-ocr/
├── app.py                 桌面界面（tkinter）：文件队列、进度、日志、拖拽
├── core.py                核心逻辑：识别、阅读顺序还原、四种格式导出
├── camera.py              实时摄像头识别窗口
├── cli.py                 命令行入口（批量/自动化）
├── run.bat                双击启动（纯 ASCII + CRLF，避免 cmd 编码问题）
├── build_exe.bat          可选：PyInstaller 打包成免安装目录
├── samples/               测试素材（3 页模拟合同扫描件、小图报销单）
├── docs/                  界面截图
└── tools/                 开发调试脚本（生成素材、界面自检、摄像头坐标校验）
```

`core.py` 与界面完全解耦，只依赖 RapidOCR / PyMuPDF / python-docx，方便改造成服务端接口或换 GUI。

## 常见问题

**识别有乱码或漏字？**
阈值调到 0.3 会多留结果，0.7 更严格。拍照件先裁掉背景、摆正，效果差别很大。

**可搜索 PDF 里搜不到关键词？**
确认搜的是识别出来的文字（可能有个别错字）；PDF 文字层是按坐标放置的，旋转过的页面搜索命中率会下降。

**输出 PDF 体积很大？**
原始扫描图按原样嵌入，不做重压缩。需要小体积时生成后用 PDF 工具降采样。

**摄像头打不开？**
先确认没被微信/钉钉/浏览器占用，换个序号再试；重新打开窗口会自动重扫设备。

**摄像头文字是反的？**
画面被设备镜像了，需要在摄像头驱动/软件里关掉镜像，程序侧无法纠正（OCR 对镜像文字无效）。

**双击 run.bat 报一堆「不是内部或外部命令」？**
批处理被改成 UTF-8 编码或 LF 换行了，Windows 的 cmd 会按 GBK 解析导致乱码。请保持 **ASCII 内容 + CRLF 换行**。

**想发给没装 Python 的同事？**
运行 `build_exe.bat`，产物在 `dist/DocOCR/`，整个文件夹拷走（含模型，体积较大）。

## 已知限制

- 手写体准确率明显低于印刷体，属模型能力边界
- 不支持竖排古籍、多栏学术排版的高级分栏还原（只按行聚类）
- 表格输出的是带空格的对齐文本，不是真正的表格结构（要结构化可接 PaddleOCR PP-StructureV3）
- 界面针对 Windows + 高 DPI 调过，其他平台可用但样式会退化
